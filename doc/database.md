md_content = """# 🏗️ معماری کامل دیتابیس پروژه Telegram Opportunity Detection & Lead Intelligence System

این سند حاوی جزئیات کامل معماری دیتابیس، ساختار ۸ جدول اصلی، دلیل وجودی هر بخش و آمادگی آن برای ارتقا از سطح MVP (Level 1) به سطح هوش مصنوعی پیشرفته (Level 2 تا Level 4) است.

---

## 🎯 فلسفه طراحی دیتابیس
معماری این دیتابیس بر اساس ۵ اصل استراتژیک محصول طراحی شده است:
1. **واحد تحلیل:** تحلیل کاربر بر پایه `Person + Source + Time + Context` است، نه صرفاً یک پیام منفرد.
2. **ارزش اصلی:** هدف پیدا کردن **قصد خرید مشتری (Customer Intent)** و تولید **لید باکیفیت (Precision Lead)** است.
3. **ارزیابی منبع:** اعتبار و کیفیت گروه (`sources`) به اندازه خود پیام اهمیت دارد.
4. **حلقه بازخورد:** ذخیره‌سازی نظرات کاربر (`feedbacks`) جهت آموزش هوشمندتر الگوریتم‌ها در آینده.
5. **توسعه‌پذیری بدون تغییرات تخریبی:** ساختار جدول‌ها از همین الان برای اضافه شدن قابلیت‌های هوش مصنوعی (ارزیابی رفتار، Vector Search و...) آماده است.

---

## 📊 1. نقشه جدول‌ها و جزئیات ساختار داده

### 1️⃣ جدول `users` (مشتریان و صاحبان کسب‌وکار)
* **دلیل ساخت:** مدیریت کاربران سیستم SaaS، لایسنس‌ها، دسترسی‌ها و تفکیک داده‌های مشتریان از یکدیگر (Multi-tenancy).
* **نقش در ارتقای محصول:** تعیین صنف کاری برای تفهیم زمینه (Context) به هوش مصنوعی در فازهای بعدی.

| نام ستون | نوع داده | کلید / محدودیت | توضیح |
| :--- | :--- | :--- | :--- |
| `id` | `SERIAL` | `PRIMARY KEY` | شناسه یکتای کاربر در سیستم |
| `email` | `VARCHAR(255)` | `UNIQUE`, `NOT NULL` | ایمیل کاربر جهت ورود |
| `hashed_password` | `VARCHAR(255)` | `NOT NULL` | رمز عبور هش‌شده و امن |
| `full_name` | `VARCHAR(100)` | - | نام کامل صاحب کسب‌وکار |
| `business_type` | `VARCHAR(100)` | - | صنف کاری (مثلاً: املاک، تعمیرات موبایل) |
| `is_active` | `BOOLEAN` | `DEFAULT TRUE` | وضعیت فعال/غیرفعال بودن حساب |
| `subscription_end` | `TIMESTAMP` | - | تاریخ پایان اشتراک لایسنس |
| `created_at` | `TIMESTAMP` | `DEFAULT CURRENT` | زمان ثبت‌نام کاربر |

---

### 2️⃣ جدول `telegram_sessions` (پل ارتباطی به تلگرام)
* **دلیل ساخت:** ذخیره کلید اتصال امن به تلگرام بدون نیاز به اخذ مجدد کد تأیید در هر بار ریستارت شدن سرور.

| نام ستون | نوع داده | کلید / محدودیت | توضیح |
| :--- | :--- | :--- | :--- |
| `id` | `SERIAL` | `PRIMARY KEY` | شناسه یکتا |
| `user_id` | `INT` | `FOREIGN KEY (users.id)` | متصل به کاربر مربوطه |
| `phone_number` | `VARCHAR(20)` | `NOT NULL` | شماره تلفن اکانت تلگرام |
| `session_string` | `TEXT` | `NOT NULL` | کلید متنی احراز هویت Telethon |
| `is_active` | `BOOLEAN` | `DEFAULT TRUE` | وضعیت فعال بودن شنود این اکانت |
| `created_at` | `TIMESTAMP` | `DEFAULT CURRENT` | زمان ثبت |

---

### 3️⃣ جدول `keywords` (موتور تعریف نیازمندی مشتری)
* **دلیل ساخت:** تعریف کلمات کلیدی مثبت (قصد خرید) و منفی (حذف اسپم) همراه با وزن‌دهی ریاضی جهت فیلتر اولیه در Level 1.

| نام ستون | نوع داده | کلید / محدودیت | توضیح |
| :--- | :--- | :--- | :--- |
| `id` | `SERIAL` | `PRIMARY KEY` | شناسه یکتا |
| `user_id` | `INT` | `FOREIGN KEY (users.id)` | متصل به کاربر |
| `word` | `VARCHAR(100)` | `NOT NULL` | کلمه یا عبارت کلیدی (مثلاً: خریدارم) |
| `type` | `ENUM` | `positive / negative` | نوع کلمه (مثبت یا منفی) |
| `weight` | `FLOAT` | `DEFAULT 1.0` | ضریب اهمیت کلمه در فرمول محاسباتی |
| `created_at` | `TIMESTAMP` | `DEFAULT CURRENT` | زمان ایجاد |

---

### 4️⃣ جدول `sources` (کیفیت‌سنجی گروه‌ها و کانال‌ها)
* **دلیل ساخت:** ارزیابی اعتبار منابع شنود و آماده‌سازی سیستم برای Level 4 (محاسبه چگالی لید و رتبه‌بندی گروه‌ها).

| نام ستون | نوع داده | کلید / محدودیت | توضیح |
| :--- | :--- | :--- | :--- |
| `id` | `SERIAL` | `PRIMARY KEY` | شناسه یکتا |
| `telegram_chat_id`| `BIGINT` | `UNIQUE`, `NOT NULL` | آیدی عددی یکتای گروه در تلگرام |
| `title` | `VARCHAR(255)` | - | نام گروه |
| `username` | `VARCHAR(100)` | - | آیدی عمومی گروه (`@group`) |
| `source_score` | `FLOAT` | `DEFAULT 50.0` | امتیاز کیفیت و اعتبار گروه (۰ تا ۱۰۰) |
| `is_active` | `BOOLEAN` | `DEFAULT TRUE` | وضعیت شنود گروه |
| `created_at` | `TIMESTAMP` | `DEFAULT CURRENT` | زمان اضافه شدن منبع |

---

### 5️⃣ جدول `persons` (پروفایل‌سازی رفتار فرستنده در طول زمان)
* **دلیل ساخت:** زیربنای Level 3 جهت بررسی مسیره خرید مخاطب (Buyer Journey) و تحلیل پرونده رفتاری فرد به جای یک پیام مجزا.

| نام ستون | نوع داده | کلید / محدودیت | توضیح |
| :--- | :--- | :--- | :--- |
| `id` | `SERIAL` | `PRIMARY KEY` | شناسه یکتا |
| `telegram_user_id`| `BIGINT` | `UNIQUE`, `NOT NULL` | آیدی عددی فرستنده در تلگرام |
| `username` | `VARCHAR(100)` | - | نام کاربری تلگرام |
| `first_name` | `VARCHAR(100)` | - | نام فرستنده |
| `last_name` | `VARCHAR(100)` | - | نام خانوادگی فرستنده |
| `phone` | `VARCHAR(20)` | - | شماره تلفن (در صورت دسترسی) |
| `topic_profile` | `JSONB` | `DEFAULT '{}'` | ساختار JSON از سوابق علاقه‌مندی‌ها و موضوعات فرد |
| `current_stage` | `VARCHAR(50)` | `DEFAULT 'unaware'` | مرحله در مسیر خرید (مثلاً ready_to_buy) |
| `updated_at` | `TIMESTAMP` | `DEFAULT CURRENT` | زمان آخرین بروزرسانی |

---

### 6️⃣ جدول `messages` (آرشیو پیام‌های خام)
* **دلیل ساخت:** نگهداری تاریخچه پیام‌های دریافت شده جهت حسابرسی، پردازش مجدد زمینه‌ای (Contextual) و ایجاد دیتاست آموزشی برای AI.

| نام ستون | نوع داده | کلید / محدودیت | توضیح |
| :--- | :--- | :--- | :--- |
| `id` | `SERIAL` | `PRIMARY KEY` | شناسه یکتا |
| `telegram_message_id`| `BIGINT` | `NOT NULL` | آیدی پیام در گروه تلگرام |
| `source_id` | `INT` | `FOREIGN KEY (sources.id)` | منبع ارسال پیام |
| `person_id` | `INT` | `FOREIGN KEY (persons.id)` | فرد فرستنده پیام |
| `raw_text` | `TEXT` | `NOT NULL` | متن کامل و خام پیام |
| `message_date` | `TIMESTAMP` | `NOT NULL` | زمان ارسال پیام در تلگرام |
| `created_at` | `TIMESTAMP` | `DEFAULT CURRENT` | زمان دریافت در سیستم |

---

### 7️⃣ جدول `leads` (خروجی اصلی و فرصت‌های فروش)
* **دلیل ساخت:** ذخیره‌سازی هشدارها (Alerts) و لیدهای کشف‌شده همراه با امتیاز محاسبه‌شده و شواهد آماری.

| نام ستون | نوع داده | کلید / محدودیت | توضیح |
| :--- | :--- | :--- | :--- |
| `id` | `SERIAL` | `PRIMARY KEY` | شناسه یکتا |
| `user_id` | `INT` | `FOREIGN KEY (users.id)` | مشتری دریافت‌کننده لید |
| `message_id` | `INT` | `FOREIGN KEY (messages.id)`| پیام مربوط به لید |
| `person_id` | `INT` | `FOREIGN KEY (persons.id)` | فرد متقاضی |
| `intent_score` | `FLOAT` | `NOT NULL` | درصد قصد خرید محاسبه شده (مثلا 85.5) |
| `lead_level` | `ENUM` | `low / warm / hot` | درجه اولویت و داغ بودن لید |
| `evidence_json` | `JSONB` | `DEFAULT '{}'` | دلایل و شواهد کشف لید (کلمات پیدا شده و...) |
| `created_at` | `TIMESTAMP` | `DEFAULT CURRENT` | زمان تولید لید |

---

### 8️⃣ جدول `feedbacks` (حلقه یادگیری و بازخورد کاربر)
* **دلیل ساخت:** ثبت بازخورد مستقیم مشتری درباره کیفیت لید جهت آموزش هوش مصنوعی و اصلاح ضریب دقت در فازهای بعدی.

| نام ستون | نوع داده | کلید / محدودیت | توضیح |
| :--- | :--- | :--- | :--- |
| `id` | `SERIAL` | `PRIMARY KEY` | شناسه یکتا |
| `lead_id` | `INT` | `FOREIGN KEY (leads.id)` | لید ارزیابی شده |
| `user_id` | `INT` | `FOREIGN KEY (users.id)` | کاربر نظر دهنده |
| `rating` | `ENUM` | `relevant / irrelevant / not_sure` | میزان مرتبط بودن لید |
| `notes` | `TEXT` | - | یادداشت اختیاری کاربر |
| `created_at` | `TIMESTAMP` | `DEFAULT CURRENT` | زمان ثبت بازخورد |
